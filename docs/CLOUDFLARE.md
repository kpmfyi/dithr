# Cloudflare deployment

The studio uses Cloudflare Workers Static Assets with the same static export as
the Vercel deployment. It needs no server, database or application secrets.
Cloudflare's HTML routing serves the exported pages at clean URLs, including
`/demos`, and serves the exported 404 page for missing paths.

## Setup

Use Node 24 or newer and install dependencies with `npm ci`.

```sh
mkdir -p .local
cp ops/cloudflare.example.json .local/cloudflare.json
./node_modules/.bin/wrangler login
```

In `.local/cloudflare.json`, set `name` to the desired Worker name and replace
the example domain with a hostname in your Cloudflare-managed zone. If the
account has multiple accounts available, also set `account_id`. Keep this file
local: deployment identities, domains and account settings are excluded from Git.

## Publish

The GitHub Actions workflow validates pull requests and automatically builds and
deploys every push to `main`, including merged PRs. Manual workflow runs deploy
only when run on `main`. Production deployments are serialized.

Set these repository Actions settings before merging:

- Variable `SEEDBANK_SITE_URL`: the public HTTPS origin used in social share cards.
- Variable `CLOUDFLARE_DEPLOY_CONFIG`: the local Cloudflare JSON config, including
  `account_id`, the existing Worker name and Custom Domain. The workflow fixes
  the assets directory and routing settings to the validated static build.
- Secret `CLOUDFLARE_API_TOKEN`: a Cloudflare API token scoped to the deployment
  account and zone, with Workers Scripts Edit, Workers Routes Edit, Zone Read
  and SSL and Certificates Edit for Custom Domain management. Use the Edit
  Cloudflare Workers token template as a starting point. Never store your
  interactive Wrangler OAuth credentials in CI.

Pull requests build without deployment credentials and never publish. Account
and domain configuration stays in GitHub settings and ignored local files.

For a manual deployment from this machine:

```sh
npm run deploy:cloudflare
```

This builds the consumer, portable code exports and all static pages, then deploys
`dist/client`. The explicit config path avoids the server deployment config
generated by the Cloudflare Vite plugin. Custom Domain routing lets Cloudflare
manage DNS and HTTPS. Review any existing DNS conflict before replacing it.

To validate the upload configuration without publishing:

```sh
npm run build:static
./node_modules/.bin/wrangler deploy --config .local/cloudflare.json --dry-run
```

After deployment, check `/`, `/demos`, `/consumer/`, a missing path, shader
rendering, a shared recipe URL and a code export on the final HTTPS hostname.
The existing Vercel deployment can remain available during migration.

References: [Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/)
and [Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).
